AUTHORITATIVE PLATFORM DESCRIPTION (identical to the constructor's platform contract; this is the source for any
tool name, signature, document-id format, page numbering or anchor syntax a task text states, so such statements
are sourced when they match it and must not be flagged as unsourced):
Tools the controller grants to every solver (use these exact names when a task text names a tool):
- artifact_read_write: read and write files by path RELATIVE to the working directory /work
  (write "results/x.json", never "/work/results/x.json" as a tool path).
- cpu_python_execution: run a Python script located under /work (relative path). A script shipped under the
  read-only public input root cannot be run directly; if the task wants the solver to use a supplied checker, say that
  the solver must first write a copy of it into /work (e.g. tools/check.py) and run the copy.
- artifact_image_view: view an image file the solver produced under /work (e.g. to inspect its own rendered PNG).
  Granted to every task type; a task may rely on it (e.g. WRITE_EVIDENCE figure checks) or ignore it.
LIT tasks additionally get the literature tools: literature.search(query, limit) -> document_id values of the form
  doc-<arXiv id>v<version>, title, version date, snippet; literature.read(document_id) -> record and abstract;
  literature.read_page(document_id, page_number) -> one-based controller pages of the pinned arXiv HTML text (not PDF
  pages); page text carries bracketed anchor markers that begin with the section sign. A citation locator must be a
  marker copied exactly from a page the solver read, or "abstract"; never print a concrete example anchor.
No other tools exist (no shell, no network, no model client for the solver to call directly).

In addition to the policy, check every public task text against the platform the solver actually runs on:
- tools are named exactly as granted. The controller grants EVERY task type exactly: artifact_read_write and
  cpu_python_execution (paths relative to /work) and artifact_image_view (view images the solver produced); LIT tasks
  additionally get literature.search / literature.read / literature.read_page. A task text that mentions viewing the
  solver's own figures (artifact_image_view, "image view") is therefore NOT an ungranted tool. Flag invented tool
  names, call signatures, locator syntaxes or helper commands, and anything beyond this list (shell, network, model API);
- no instruction to execute a script directly from the read-only public input root (/inputs/public or
  $MRH_PUBLIC_ROOT); a supplied checker must first be copied into /work;
- LIT citation locators are anchor markers copied from read pages, or "abstract"; no concrete example anchor printed;
- the output contract and task.md name the same deliverable files and JSON fields; fixed JSON structures ship a schema;
- any quantity or relation stated in more than one public file is stated identically.
Report a violation as an issue under the most specific applicable policy rule; it is a repairable contract defect.
